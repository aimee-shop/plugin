# CLAUDE.md - aimee-claude-plugin

Home of the public Aimee agent plugin (`aimee`): the
Claude Code plugin + marketplace manifest, plus generated Agent Plugins 1.0
(Cursor, Codex, VS Code/Copilot, Kiro), Grok Build, and OpenAI ChatGPT/Codex
packagings. Covers two tracks: merchant/storefront and app/connector developer.

## Rules

- main-direct branching: feature branches merge straight to `main`.
  `claude plugin marketplace add` pulls from main, so main must always be
  installable.
- Single source of truth is `aimee-shop/` (directory name is internal).
  `dist/agent-plugins/`, `dist/grok/`, `dist/openai/`,
  `.grok-plugin/marketplace.json`, `.cursor-plugin/plugin.json`, and
  `.agents/plugins/marketplace.json` are GENERATED by
  `scripts/build-packagings.mjs` -- never edit them by hand.
  After any change to skills, agents, manifests, or the MCP pointer, run
  `node scripts/build-packagings.mjs` and commit the regenerated outputs;
  CI (`packagings` job) fails on stale outputs.
- Skill content must stay client-agnostic: no bare "Claude Code" assumptions;
  Claude Code specifics only as parentheticals. Skill cross-references are
  written "the `<name>` skill (`/aimee:<name>`)" (or ", `/aimee:<name>`"
  when already inside parentheses) -- the Claude Code packaging keeps the
  slash form and the generator strips it for Agent Plugins / Grok. Agent Plugins skill
  frontmatter allows only name/description/license/compatibility/metadata/
  allowed-tools -- the generator folds extra keys into `metadata`, and skills
  violating the Agent Skills spec are silently skipped by those clients.
- Agents ship only in the Claude Code and Grok packagings; Agent Plugins 1.0
  and the OpenAI adapter carry skills + MCP config only. Skills must not
  depend on agents being present.
- The MCP server is NOT in this repo. `aimee-shop/.mcp.json` points at the
  hosted MCP server (`https://mcp.aimee.shop/mcp`) as a remote `type: http`
  server; Claude Code does the OAuth dance on first use. There is no local
  process and no npm dependency. The MCP server key (`aimee`) is an
  internal id and does not change.
- The skills/agents reference the hosted server's tool surface:
  `whoami`, `search_knowledge`, `get_sdk_method`, `get_type_definition`,
  `get_setup_checklist`, `introspect_api`, `set_scope`, and flag-gated
  `use_sdk`. `search_knowledge` and `use_sdk` may be disabled on a given
  deployment -- skills must degrade gracefully (docs.aimee.shop / admin UI).
  When the surface changes, update the skills/agents here in the same
  release window. There are no `login` / `select_tenant` tools -- auth and
  tenant context come from the OAuth connection. Scaffolding is a local
  skill (`/aimee:scaffold`), not an MCP tool.
- Aimee public plugin versions start at `0.0.1`. Do not resume the pre-Aimee
  0.5.x series. Bump versions in BOTH `.claude-plugin/marketplace.json`
  (plugins[0].version) and `aimee-shop/.claude-plugin/plugin.json` together
  ON EVERY CONTENT CHANGE.
  If the version is unchanged, `claude plugin marketplace update` +
  `claude plugin update` keep serving the cached old content SILENTLY (no
  error) -- installs will not see new skills/agents/.mcp.json. Verify after
  release: `ls ~/.claude/plugins/cache/aimee/aimee/<version>`.
  Marketplace slug stays `aimee`; plugin id is `aimee`.
- This plugin is client-facing: no internal tooling references and no
  internal URLs (aimee.shop domains only) in any tracked file.
- The GitHub repository is a read-only distribution mirror; changes land in
  the canonical repository and sync automatically. External pull requests
  cannot be merged -- direct contributors to support@aimee.shop.
